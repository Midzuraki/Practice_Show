# CapyCafe — Информационная система управления меню кафе

Простое и надежное консольное приложение на **Python** для управления базой данных блюд ресторанного меню. Проект разработан в рамках учебной практики и оптимизирован для работы на любом компьютере без предварительной настройки.

## Особенности проекта

* **Модульная архитектура:** Логика полностью разделена. Пользовательский консольный интерфейс находится отдельно от SQL-запросов и логики работы с БД.
* **Абсолютная портативность:** Проект использует динамическое определение путей (`pathlib`), поэтому он запустится на любом ПК, независимо от того, в какую папку его скачали.
* **Безопасность данных:** Интеграция с SQLite поддерживает каскадный контроль целостности данных (`PRAGMA foreign_keys = ON`).

## Функционал приложения

1. **Добавление блюда:** Автоматически подтягивает существующие категории из БД и связывает новое блюдо с выбранным разделом. Проверяет корректность ввода цен.
2. **Удаление блюда:** Безопасное удаление по ID с проверкой на наличие связей в других таблицах.
3. **Редактирование блюда:** Позволяет быстро обновить название, описание, цену или категорию, сохранив старые данные, если поле ввода осталось пустым.
4. **Просмотр БД (Admin Only!!!):** Динамически сканирует структуру базы данных, рассчитывает ширину колонок и выводит все таблицы проекта в виде красивых, выровненных текстовых сеток.

## Инструкция по запуску

Для работы приложения никаких сторонних библиотек устанавливать не нужно — используются встроенные модули `sqlite3` и `pathlib`.

Запустите run.bat или выполните в консоли из корня проекта команду:
```bash
python -m main.main
```

Для развертывания проекта из репозитория и установки утилит автоматизированной сборки выполните:
```bash
pip install .
```

## Решение возможных проблем (Траблшутинг)

### 1. Ошибка `ModuleNotFoundError: No module named 'database'`
* **Почему происходит:** Python при обычном запуске из подпапок теряет корень проекта и не понимает, откуда импортировать модули.
* **Решение:** Добавьте следующий блок в самый верх файла `main/main.py` (до любых других импортов):

```python
import sys
from pathlib import Path

# Скопировать и вставить в самый верх main.py
PROJECT_ROOT = Path(__file__).resolve().parent.parent
if str(PROJECT_ROOT) not in sys.path:
    sys.path.insert(0, str(PROJECT_ROOT))
```

### 2. Ошибка `NameError: name 'sqlite3' is not defined`
* **Почему происходит:** В процессе редактирования кода был непреднамеренно удален или закомментирован импорт встроенной библиотеки.
* **Решение:** Проверьте самые первые строчки файла `main/main.py`. Там обязательно должен присутствовать импорт:
  ```python
  import sqlite3
  ```

### 3. Ошибка сборщика `Multiple top-level packages discovered in a flat-layout`
* **Почему происходит:** Утилита `setuptools` путается в структуре проекта при вызове `pip install .`, пытаясь собрать проект как публичную библиотеку.
* **Решение:** Проблема решена добавлением спецификации пакетов в файл конфигурации `pyproject.toml` в секцию `[tool.setuptools]`. Изменять структуру директорий вручную не требуется.

### 4. Крах исполняемого файла с ошибкой `Failed to load Python DLL`
* **Почему происходит:** Нарушена целостность скомпилированной папки приложения, либо механизмы безопасности операционной системы Windows блокируют загрузку библиотеки `python314.dll`.
* **Решение:** Добавьте рабочую директорию в список исключений антивирусного ПО. Выполните чистую пересборку пакета без использования устаревшего кэша с помощью команды:
  ```bash
  pyinstaller --onedir --clean --distpath=. --paths=. --name=CapyCafe main/main.py
  ```


## Подробности реализации CapyCafe

Этот раздел дополняет исходную документацию и описывает текущие модули проекта, отчёты и автоматические проверки.

### Что находится в папках исходного кода

- `.github/workflows/` — сценарии GitHub Actions. Файл `python-checks.yml` запускает компиляцию и тесты на Python 3.10, 3.11, 3.12 и 3.13.
- `main/` — точка входа и текстовый интерфейс. `main.py` отвечает за вход по ID сотрудника, меню с учётом роли, ввод данных, отображение заказов и вызов модулей базы данных.
- `database/` — SQL-схема, начальные данные и модули работы с SQLite.
- `database/scripts/authorization/` — выбор сотрудника и операции со списком сотрудников.
- `database/scripts/createdb/` — вспомогательный сценарий создания и заполнения базы.
- `database/scripts/dishes/` — работа с блюдами, категориями, поиском, сортировкой и просмотром таблиц.
- `database/scripts/dishes/old_menu/` — отдельные старые сценарии добавления и удаления блюд, сохранённые в проекте.
- `database/scripts/orders/` — создание заказов, управление позициями, подсчёт сумм, фильтрация, статусы и отмена.
- `database/scripts/reports/` — SQL-запросы и расчёты для отчётов.
- `database/scripts/test/` — основной набор модульных тестов приложения.
- `tests/` — дополнительные регрессионные тесты, проверяющие согласованность отчётов и исключение отменённых заказов из рейтинга блюд.
- `database/schema.sql` — структура шести таблиц базы данных.
- `database/data.sql` — демонстрационные записи для первоначального наполнения базы.
- `pyproject.toml` — метаданные проекта и настройки сборки.
- `run.bat` — сценарий подготовки окружения, сборки и запуска Windows-версии.
- `README.md` — основная документация проекта.

### Модель данных

В базе используются шесть таблиц:

| Таблица | Назначение |
| --- | --- |
| `categories` | Категории меню |
| `employees` | Сотрудники и должности |
| `order_statuses` | Справочник статусов |
| `dishes` | Название, описание, цена, доступность и категория блюда |
| `orders` | Дата, столик, сотрудник и статус заказа |
| `order_items` | Состав заказа, количество и цена на момент оформления |

Цена в позиции заказа сохраняется отдельно от текущей цены блюда. Поэтому изменение цены в меню не меняет сумму ранее созданного заказа. Отмена сохраняет запись заказа и его историю, а не удаляет её.

### Отчёты

- **Рейтинг блюд** — количество заказанных порций и сумма по позициям в заказах, которые не были отменены.
- **Выручка за период** — количество и сумма оплаченных заказов за заданную дату или период.
- **Эффективность официантов** — число оплаченных заказов и выручка по официантам за выбранный период.
- **Отменённые заказы** — список отменённых заказов и их потенциальная стоимость. Эта сумма не считается фактической выручкой.

### Проверка проекта

Для запуска тестов из корневой папки:

```bash
python -m compileall -q main database tests
python -m unittest database.scripts.test.tests
python -m unittest tests.test_report_alignment
```

В GitHub Actions эти проверки выполняются для Python 3.10–3.13. Набор включает 147 основных тестов и 7 регрессионных тестов на каждой версии Python.

### Важные ограничения

- Вход по ID предназначен для демонстрации выбора роли; пароль и подтверждение личности не используются.
- Проект не реализует сетевую многопользовательскую работу, интеграцию с кассой или складской учёт.
- Проверка базы при запуске выявляет отсутствие обязательных таблиц, но не выполняет полноценные миграции несовместимой существующей схемы.
- Перед ручным изменением, удалением или восстановлением рабочей базы рекомендуется сделать резервную копию.
