# «Причал» — информационная система управления кафе

Учебное консольное приложение на Python для учёта меню, сотрудников и заказов кафе. Данные хранятся локально в SQLite. Интерфейс и работа с базой разделены по модулям.

## Возможности

### Меню и категории
- Просмотр действующего меню с группировкой по категориям.
- Добавление, редактирование и удаление блюд.
- Проверка цены и категории при добавлении блюда.
- Если блюдо уже использовано в заказах, его нельзя физически удалить; вместо этого можно пометить его как недоступное.
- Просмотр списка категорий, добавление, переименование и удаление категорий.
- Поиск блюд по части названия, фильтрация по категории и сортировка по цене.

### Сотрудники и доступ
- Просмотр списка сотрудников.
- Добавление, редактирование и удаление сотрудников с проверкой ссылок из заказов.
- При запуске сотрудник выбирает свой ID. Приложение показывает список доступных ID — это учебный механизм выбора пользователя, **не защищённая авторизация**: паролей и проверки личности нет.
- Набор пунктов меню зависит от должности: администратор, официант, повар или бармен.
- При создании заказа и смене статуса проверяются ограничения, заданные для должности.

### Заказы
- Создание заказа для столика с номером от 1 до 12.
- Добавление блюд и количества; цена фиксируется в заказе на момент оформления.
- Просмотр активных заказов с датой, столиком, сотрудником, статусом и итоговой суммой.
- Просмотр состава заказа, стоимости каждой позиции и общей суммы.
- Изменение статуса с проверкой допустимых переходов и прав должности.
- Отмена заказа. Оплаченные и отменённые заказы нельзя редактировать.
- Просмотр заказов с фильтрацией по статусу и диапазону дат.

### Отчёты и база данных
- **Рейтинг блюд:** количество проданных порций и выручка по оплаченным заказам.
- **Выручка за период:** количество оплаченных заказов и общая сумма за выбранную дату или диапазон дат.
- **Эффективность официантов:** число оплаченных заказов и выручка каждого официанта за выбранный период.
- **Отменённые заказы:** список отмен с потенциальной стоимостью.
- **Просмотр БД:** вывод таблиц SQLite в консоль в виде выровненных колонок.

## Технологии и структура БД

- Python 3.10 или новее.
- SQLite через стандартный модуль `sqlite3`; сторонние библиотеки для обычного запуска не нужны.
- Шесть таблиц: `categories`, `employees`, `order_statuses`, `dishes`, `orders`, `order_items`.
- Внешние ключи и ограничения целостности включены через `PRAGMA foreign_keys = ON`.
- Цены и состав уже созданного заказа сохраняются в `order_items.price_at_order`, чтобы последующее изменение цены блюда не меняло старый заказ.

## Запуск из исходников

Выполняйте команды из корневой папки репозитория.

```bash
python --version
python -m main.main
```

Если файл базы отсутствует или запрос к таблице `employees` не выполняется, приложение создаёт таблицы SQLite и добавляет демонстрационные записи. Если таблица `employees` доступна, база считается существующей и используется как есть: автоматической миграции или восстановления остальных таблиц нет.

## Запуск в Windows

Можно запустить `run.bat`. Скрипт предназначен для сборки консольного приложения через PyInstaller и последующего запуска `CapyCafe.exe`.

Если собираете вручную, установите PyInstaller и выполните команду из корня проекта:

```bash
python -m pip install pyinstaller
python -m PyInstaller --onedir --console --name CapyCafe --distpath . main/main.py
```

При переносе собранной версии сохраняйте расположение каталогов:

```text
папка_проекта/
├── CapyCafe/
│   ├── CapyCafe.exe
│   └── _internal/
└── database/
    └── capycafe.db
```

Не заменяйте рабочую базу демонстрационной, если в ней уже есть данные.

## Проверка

Компиляция Python-файлов:

```bash
python -m compileall main database tests
```

Запуск автоматических тестов:

```bash
python -m unittest discover -s tests -v
python -m unittest discover -s database/scripts/test -v
```

Тесты проверяют ограничения SQLite, операции с категориями и блюдами, создание и изменение заказов, переходы статусов и права ролей, фильтрацию, детали заказа, расчёт рейтинга и выручки, эффективность официантов и стоимость отменённых заказов.

## Соответствие отчёту и известные ограничения

Реализованы сценарии учёта меню, категорий, сотрудников, заказов и статусов, просмотр состава заказа с построчной стоимостью и итогом, рейтинг блюд, выручка, эффективность официантов и отчёт по отменённым заказам.

По просьбе сохранить исходный вход оставлен выбор сотрудника по ID и меню по должностям. Это отличается от варианта требований, где авторизация и разграничение доступа обозначены как не входящие в объём работ. Если отчёт должен строго описывать текущую реализацию, этот пункт в отчёте необходимо согласовать с кодом. При этом текущий вход не использует пароли и не предназначен для защиты реальной системы.

Проект учебный и работает с локальной SQLite-базой. В нём нет полноценной парольной аутентификации, сетевого многопользовательского режима, кассовой интеграции или складского учёта.
