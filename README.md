# CapyCafe

**CapyCafe** — учебная консольная информационная система для управления основными операциями кафе. Приложение написано на Python, использует SQLite и запускается в терминале Windows или из исходного кода.

## Возможности

### Меню и категории

- Просмотр доступного меню с группировкой блюд по категориям.
- Поиск блюда по части названия без учёта регистра.
- Фильтрация по категории и сортировка по цене.
- Добавление и редактирование блюда, включая описание, цену, категорию и доступность.
- Удаление блюда, если оно ещё не использовалось в заказах. Использованные блюда можно пометить как недоступные, сохранив историю заказов.
- Просмотр, создание, переименование и удаление категорий. Категорию с блюдами удалить нельзя.

### Сотрудники

- Просмотр списка сотрудников.
- Добавление, редактирование и удаление сотрудника при отсутствии связанных заказов.
- Поддерживаемые должности: администратор, официант, повар и бармен.
- Учебный вход с выбором сотрудника по ID. Набор пунктов меню зависит от выбранной должности.

> **Важно:** вход по ID — демонстрационный механизм выбора профиля, а не безопасная аутентификация. Пароли и проверка личности не используются.

### Заказы

- Создание заказа для столика с номером от 1 до 12.
- Добавление нескольких блюд и объединение повторяющихся позиций.
- Сохранение цены блюда на момент оформления заказа, чтобы изменение цены в меню не переписывало историю.
- Просмотр активных заказов с датой, столиком, сотрудником, статусом и итоговой суммой.
- Просмотр состава заказа с количеством, ценой каждой позиции и итогом.
- Добавление, изменение количества и удаление позиции в заказе, пока заказ не оплачен и не отменён.
- Изменение статуса с проверкой допустимого перехода и роли сотрудника.
- Отмена заказа без удаления его истории.
- Просмотр заказов с фильтрацией по статусу и диапазону дат.

### Отчёты

- **Рейтинг блюд** — количество заказанных порций и сумма по позициям в заказах, которые не были отменены.
- **Выручка за период** — количество оплаченных заказов и сумма оплаченных позиций за дату или диапазон дат.
- **Эффективность официантов** — количество оплаченных заказов и выручка по каждому официанту за выбранный период.
- **Отменённые заказы** — перечень отменённых заказов с их потенциальной стоимостью.

### Просмотр базы данных

Администратор может вывести содержимое таблиц SQLite в консоль в виде таблиц с выровненными колонками.
Для запуска приложения из исходного кода сторонние Python-библиотеки не требуются. PyInstaller нужен только для сборки исполняемого файла.

## Архитектура

Приложение разделено на консольный интерфейс и модули доступа к данным:

- `main/main.py` — меню пользователя, ввод данных, форматирование вывода и запуск приложения.
- `database/scripts/dishes/menu_manager.py` — операции с категориями и блюдами.
- `database/scripts/authorization/user_manager.py` — операции с сотрудниками.
- `database/scripts/orders/order_manager.py` — создание и изменение заказов, статусы, состав и расчёт суммы.
- `database/scripts/reports/report_manager.py` — запросы, используемые отчётами.
- `database/schema.sql` и `database/data.sql` — схема и начальные записи базы данных.

Для запросов к SQLite используются параметры SQL, а внешние ключи включаются через `PRAGMA foreign_keys = ON` в соединениях модулей работы с данными. Операции изменения данных выполняются в транзакциях; при ошибке изменения откатываются.

При запуске приложение проверяет наличие всех шести обязательных таблиц. Если база отсутствует или обязательная таблица не обнаружена, приложение запускает встроенное создание таблиц и добавление демонстрационных данных. Это не полноценная система миграций: существующая база с несовместимой структурой автоматически не преобразуется, поэтому перед восстановлением или ручным изменением БД необходимо сделать резервную копию.

## Модель данных

В базе данных используются шесть таблиц:

| Таблица | Назначение |
| --- | --- |
| `categories` | Категории меню |
| `employees` | Сотрудники и их должности |
| `order_statuses` | Справочник статусов заказа |
| `dishes` | Блюда, описания, цены и доступность |
| `orders` | Заказы, дата, столик, сотрудник и статус |
| `order_items` | Позиции заказа, количество и цена на момент оформления |

### Связи

- `dishes.category_id → categories.id`
- `orders.employee_id → employees.id`
- `orders.status_id → order_statuses.id`
- `order_items.order_id → orders.id`
- `order_items.dish_id → dishes.id`

Внешние ключи и ограничения БД защищают ссылочную целостность. Цена позиции сохраняется в `order_items.price_at_order`; итог заказа рассчитывается как сумма произведений количества на сохранённую цену. Номер столика ограничен диапазоном 1–12, цена и количество должны быть больше нуля, а одна и та же позиция блюда не дублируется в пределах заказа.

### Статусы заказа

| ID | Статус | Допустимый следующий этап |
| ---: | --- | --- |
| 1 | Принят | Готовится или Отменён |
| 2 | Готовится | Готов или Отменён |
| 3 | Готов | Выдан |
| 4 | Выдан | Оплачен |
| 5 | Оплачен | Завершён; изменения состава запрещены |
| 6 | Отменён | Завершён; изменения состава запрещены |

Оплаченные и отменённые заказы сохраняются в базе. Отмена не удаляет запись заказа.

## Пользовательские роли

| Роль | Основные возможности |
| --- | --- |
| Администратор | Управление меню, категориями и сотрудниками; оформление и сопровождение заказов; просмотр базы данных и отчётов |
| Официант | Просмотр меню, создание заказов, работа с заказами и их статусами в пределах разрешённых переходов |
| Повар | Просмотр меню и заказов, изменение кухонных статусов |
| Бармен | Просмотр меню и заказов, изменение статусов, предусмотренных для бармена |

Ролевые ограничения применяются в сценариях приложения и проверяются при изменении статуса заказа. Поскольку вход производится только по ID, эти ограничения предназначены для демонстрации учебного процесса и не должны рассматриваться как механизм безопасности для реальной эксплуатации.

## Требования

- Python **3.10 или новее**.
- Windows для запуска `run.bat`; исходный код может запускаться в другой ОС при наличии совместимой версии Python.
- Доступ на запись в каталог проекта, чтобы создать файл базы данных.
- PyInstaller — только если требуется сборка `.exe`.

## Запуск из исходного кода

Откройте терминал в корневой папке проекта и выполните:

```bash
python --version
python -m main.main
```

При первом запуске приложение создаст `database/capycafe.db` и заполнит её демонстрационными данными. Если в проекте уже есть база с данными, приложение использует её. Перед ручным удалением или заменой базы сохраните резервную копию.

## Запуск в Windows

Запустите `run.bat` из корневой папки проекта. Скрипт создаёт виртуальное окружение `.venv`, устанавливает PyInstaller, собирает приложение и запускает `CapyCafe.exe`.

Для ручной сборки:

```bash
python -m venv .venv
.venv\\Scripts\\activate
python -m pip install --upgrade pip
python -m pip install pyinstaller
python -m PyInstaller --onedir --console --name CapyCafe --distpath . main/main.py
```

Ожидаемое расположение файлов после сборки:

```text
Practice_Show/
├── CapyCafe/
│   ├── CapyCafe.exe
│   └── _internal/
└── database/
    └── capycafe.db
```

Сохраняйте каталог `database` рядом с каталогом собранного приложения. Не заменяйте рабочую базу демонстрационной, если в ней уже содержатся нужные данные.

## Ограничения

- Проект предназначен для учебной демонстрации и локального использования.
- Вход по ID не использует пароль и не подтверждает личность пользователя.
- Сетевая работа нескольких клиентов, удалённый сервер БД и синхронизация между устройствами не реализованы.
- Нет интеграции с кассой, эквайрингом, складскими остатками или внешними системами.
- Автоматическое обновление схемы существующей БД не реализовано.
- Отчёты рассчитываются по данным, которые сохранены в заказах; потенциальная стоимость отменённого заказа не является фактической выручкой.

## Лицензирование и назначение

CapyCafe — учебный проект для демонстрации разработки консольного приложения, организации модулей Python, работы с реляционной базой SQLite, обработки заказов и формирования отчётности. Перед использованием в реальном заведении потребуются полноценная аутентификация, аудит действий, резервное копирование, миграции схемы, контроль доступа и проверка требований к финансовым операциям.
